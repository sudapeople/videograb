# 설계와 검증

작성일 : 2026-11-16

## 1. 구조

`src/VideoGrab.swift` 한 파일에 전부 있다.

| 구성 | 역할 |
|---|---|
| `VideoGrabApp` | 창 1개. 편집 메뉴의 붙여넣기 묶음을 "링크 붙여넣기(⌘V)" 로 바꿔 창 어디서든 동작 |
| `DownloadStore` | 클립보드에서 링크 추출(`NSDataDetector`), 항목마다 yt-dlp 프로세스 실행 |
| `DownloadItem` | 한 다운로드의 제목·진행률·상태·파일 경로 |
| `ContentView` / `ItemRow` | 목록, 진행 막대, 저장 위치 표시·변경 |

## 2. yt-dlp 호출

```
yt-dlp --no-playlist -f "bv*+ba/b" --merge-output-format mp4 --no-mtime
       -P <저장 위치> -o "%(title)s.%(ext)s"
       --newline --progress
       --print "before_dl:TITLE %(title)s"
       --print "after_move:FILE %(filepath)s"
       --progress-template "download:PROG %(progress._percent)s"
       <링크>
```

- 출력 줄 앞머리(`TITLE`, `PROG`, `FILE`, `ERROR:`)로 화면을 갱신한다
- 맥 앱은 셸 PATH 를 물려받지 않아서 `/opt/homebrew/bin` 을 PATH 앞에 넣어 ffmpeg·deno 를 찾게 한다
- `--no-mtime` : 파일 날짜를 업로드 날짜가 아니라 받은 날짜로 둔다 (Finder 정렬용)

## 3. 결정 사항

- 컨테이너 mp4 : 기존 4K 설정과 같게 맞춤. AV1·VP9·Opus 도 mp4 에 그대로 담는다
- 동시 다운로드 제한 없음 : 붙여넣은 만큼 바로 시작. 필요하면 대기열을 넣는다
- 다운로드 기록 저장 안 함 : 앱을 닫으면 목록이 비워진다. 파일은 저장 위치에 그대로 남는다

## 4. 시험 결과 (2026-11-16, M3 Pro, macOS 27.2.1, yt-dlp 2026.10.26)

| 시험 | 결과 |
|---|---|
| 재생목록 붙은 4K HDR 링크 붙여넣기 | 3840x2160 AV1 HDR(PQ) 60fps + Opus, 원본 최고 포맷과 일치. 45초 영상 133MB |
| QuickTime(AVFoundation) 재생 가능 여부 | 영상·오디오 트랙 모두 재생 가능 |
| 같은 영상 다시 붙여넣기 | 다시 받지 않고 바로 "완료", Finder 보기 정상 |
| 한글 문장 속에 섞인 링크 | 링크만 뽑아냄. 404 오류가 빨간 글씨로 표시, "다시 받기" 버튼 노출 |
| 5분짜리 4K 영상 받는 중 취소 | yt-dlp·ffmpeg 프로세스 모두 종료, `.part` 조각만 남음 |

## 5. 알려진 한계

- VP9 로만 제공되는 4K 영상은 QuickTime 에서 안 열릴 수 있다. IINA·VLC 로 연다
- 서명이 애드혹이라 다른 맥에 복사하면 Gatekeeper 경고가 난다
- 유튜브가 막으면 `brew upgrade yt-dlp` 가 해결책. 앱 재빌드는 필요 없다
